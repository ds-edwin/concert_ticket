# JUKEBOX — 3D concert ticket

네온 공연 티켓: 드래그 회전, 셋리스트, 악기별 참가자 명단, 1~1000번 티켓 발급, 확인 후 접힘 효과.

## 현재 상태

확정 셋리스트 16곡과 Google Apps Script 설치 코드가 준비되었습니다. docs/config.js의 endpoint가 비어 있으면 샘플 모드로 동작하며 실제 신청 정보를 전송하지 않습니다.

## Google 연결 — 한 파일 설치

1. 사용할 티켓관리 Google Sheet에서 **확장 프로그램 → Apps Script**를 엽니다.
2. [apps-script/INSTALL.gs](apps-script/INSTALL.gs)의 전체 내용을 Code.gs에 붙여 넣고 저장합니다. 이 파일에는 통신용 HTML도 포함되어 있습니다. 별도 Bridge 파일은 필요하지 않습니다.
3. 상단 함수 선택에서 **setup → 실행**을 선택하고 소유자 계정으로 Google 권한을 승인합니다.
4. **배포 → 새 배포 → 웹 앱**에서 실행 사용자는 **나**, 액세스 권한은 **모든 사용자**로 지정합니다.
5. 생성된 /exec 주소를 docs/config.js의 endpoint에 넣습니다.

시트 ID는 바인딩된 문서에서 읽어 비공개 스크립트 속성에 저장합니다. 이 저장소에는 명부 데이터나 시트 주소를 넣지 않습니다.

### 시트 구조

참석자 탭에는 입력일시 / 연번 / 이름 / 연락처_뒷번호 / 체크여부 / 하고 싶은 말 / _요청키를 사용합니다. 열 이름으로 찾으므로 7개 열의 순서를 바꾸어도 인식합니다. _요청키는 숨김 처리합니다. 연락처 뒷번호는 텍스트로 저장해 앞자리 0을 유지합니다.

셋리스트는 주최자가 확정한 16곡을 docs/config.js에 저장합니다. 시트를 조회하거나 캐시로 덮어쓰지 않으며, 1~15번만 YouTube 아이콘 링크가 있습니다. 16번 Blue rain에는 링크가 없습니다.

문서의 파일명은 바꾸어도 됩니다. 내부 탭 이름 참석자 / 셋리스트와 열 제목은 유지하세요. 실제로 연결되는 문서는 setup을 실행한 스프레드시트이며, 같은 이름의 다른 문서와는 별개입니다.

실제 신청을 받기 전 시트 공유 범위는 **제한됨**으로 설정합니다. 웹 앱은 공개 셋리스트와 해당 브라우저의 티켓만 반환합니다.

## 기존 서버 연결 업데이트

기존 설치에는 [apps-script/HTTP-UPDATE.gs](apps-script/HTTP-UPDATE.gs)를 새 HTTP.gs 파일로 추가하고 저장한 다음, **배포 → 배포 관리 → 기존 배포 → 연필 → 버전: 새 버전 → 배포**를 선택합니다. 기존 URL과 설정, 명부를 유지하며 setup 재실행은 필요 없습니다. INSTALL.gs 전체를 최신 파일로 교체했다면 이 파일을 추가하지 마세요.

[서버 업데이트 도우미](https://ds-edwin.github.io/concert_ticket/server-update.html)에서 코드를 복사하고, 발급 없이 새 서버 응답을 확인할 수 있습니다.

웹사이트는 JSON POST 방식의 서버가 있는지 확인한 후 사용합니다. Google 쿠키는 전송하지 않으며 요청키와 입력값은 POST 본문에만 넣습니다. 서버 업데이트 전에는 기존 iframe 통신을 유지합니다. 이 전환 중에는 새 방식의 실서비스 검증이 완료되었다고 간주하면 안 됩니다.

## GitHub Pages

저장소 **Settings → Pages → Build and deployment → Deploy from a branch**를 선택합니다. Branch는 **main**, Folder는 **/docs**로 저장합니다. 공개 웹사이트에는 docs 폴더만 사용합니다.

## 확인 기능

- 발급된 티켓의 오른쪽 아래 매니저 확인을 누르면 해당 행에 O를 기록합니다.
- 성공 응답 후 점선을 경계로 하단 절취 부분이 뒤로 28도 접힙니다.
- 시트에서 직접 O를 넣거나 지우면 열린 페이지에서 30초 간격 및 화면 복귀 시 반영됩니다.
- 버튼에 별도 관리자 인증은 없습니다. 티켓 소지자도 자신의 티켓을 확인할 수 있습니다.
- 이름·연락처 뒷번호 조합으로 재발급을 제한하지 않습니다. 브라우저 요청키로 재시도 중복만 방지합니다.

## 개발 및 검증

`node --test tests/backend.test.cjs tests/client-api.test.cjs` — 서버 동작 22개와 브라우저 통신 12개 검증. 설치용 INSTALL.gs를 대상으로 HTTP 발급·복원·확인도 검사합니다.

`node scripts/serve.cjs` — 로컬 웹 미리보기.

실제 연결 확인 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록합니다. 세로 원본 이미지는 그대로 사용하고, 이름과 번호를 넣는 절취 부분은 화면과 PNG 저장 시 추가합니다.
